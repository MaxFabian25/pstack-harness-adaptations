### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.claude/worktrees/x` or `~/.codex/worktrees/<id>/myrepo` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section. The transcript check covers every candidate, worktree or not. A missing transcript folder may be archived, per [harnesses.md](../references/harnesses.md) (Transcripts), so search the archive. Finish every check before the approval question in step 4. A check you cannot finish goes into that question as an option to wait for it.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm that each removed path is gone and that its parent folder shrank by the removed bytes. Drive free space moves with every other process on the machine, so it is context, not proof. When it moves far more than the removal explains, re-check the paths the user said to keep. On Windows, read free space with `(Get-PSDrive C).Free`, because Git Bash's `df -h /` reports Git's install mount.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, `~/Library/Application Support/Claude` (`Cache`, and `vm_bundles`, which balloons), old harness transcripts per [harnesses.md](../references/harnesses.md) (Transcripts), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

**Files outside git.** Installers, extracted archives, and run scratch have no branch to restore from, so three steps change. In step 1, inventory each exact path with its size and SHA-256 instead of running the audit. In step 4, get approval path by path, and list anything beyond the user's own estimate as a separate item. In step 5, re-check each approved path against the inventory immediately before removal, delete only listed paths, and refuse any path outside the approved roots and any link or junction. Build those checks as a script (principle-build-the-lever) that takes its roots as a parameter, and prove its refusals on a fixture in your own temp folder first.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** bytes removed per path, drive free space before and after as context, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
